# 第四章 实验设计与结果分析

本章围绕本文的多表多跳查询实验展开结果分析。考虑到本文同时关注多表检索效果与 Text-to-SQL 生成能力，因此本章的实验也分为两部分：第一部分是多表检索实验，重点分析不同检索策略在二表和三表场景下的效果差异；第二部分是 Text-to-SQL 实验，重点分析不同原始大语言模型在统一标准表头条件下的 SQL 生成能力。

## 4.1 实验设置

### 4.1.1 实验总体思路

本文按照多表检索实验与 Text-to-SQL 实验两部分进行设置。对于多表检索任务，系统输入为自然语言问题与全局表池，输出为 Top-K 候选表集合，并使用多种检索指标进行评价；对于 Text-to-SQL 任务，系统不使用检索结果作为输入，而是直接采用样本对应的标准答案表头（Oracle Schema），以减少检索误差对 SQL 生成能力评估的干扰。

这种实验设置的核心目标有两点：一是尽可能清晰地区分“检索不足”和“SQL 生成不足”这两类误差来源；二是分别观察不同检索策略与不同大模型在复杂多表场景下的能力边界。

### 4.1.2 多表检索实验设置

多表检索实验围绕本文第三章设计的 MTR 系列方法展开。为了与论文思路和工程实现过程相对应，本文在实验中比较了四种代表性方案：

（1）E3\_PAPER：接近原始论文伪代码的 paper-like 完整 MTR 版本，用作对照组；

（2）E3：本文实现的完整 MTR 版本，在问题分解基础上引入平均语义得分、最大连通性截断和残差平滑；

（3）E4\_HYBRID：在 E3 基础上进一步加入不确定性门控，仅在首轮语义排序置信度不足时触发传播；

（4）E5\_HYBRID\_LOCAL：在 E3 基础上进一步引入局部扩展与候选池内重排，将传播限制在种子表及其邻居构成的局部范围内。

上述方法均使用问题分解模块和表间结构关系传播模块，但在传播触发条件与传播范围上存在差异。实验分别在二表场景和三表场景上进行，并根据样本真实所需表数设定最终评估的 Top-K：二表任务采用 Top-2 进行结果统计，三表任务采用 Top-3 进行结果统计。

在评估流程上，系统首先对每个问题执行问题分解，然后计算问题（或子问题）与候选表之间的语义相似度；接着根据不同方法的设定，决定是否进行结构传播、是否执行门控、以及传播范围是全局表池还是局部候选池；最后对候选表重新排序并输出最终 Top-K 结果。

### 4.1.3 Text-to-SQL 实验设置

Text-to-SQL 实验采用统一的 API 评测方式进行。本文基于阿里百炼平台的 OpenAI 兼容接口，在相同提示词模板、相同测试集和相同输出格式约束下，比较多个原始大语言模型的 SQL 生成能力。纳入实验的模型包括：

- qwen3.6-flash
- deepseek-v4-flash
- kimi-k2.6
- MiniMax-M2.5
- glm-5

在具体实现中，所有模型的输入均由“自然语言问题 + 标准表头（仅保留表名和列名）”组成，系统要求模型仅输出如下 JSON 格式：

```json
{"SQL": "<generated_sql>"}
```

为保证实验可比性，评测过程中统一设置温度为 0.0，最大生成长度为 256。系统对每条测试样本记录模型原始输出、JSON 解析结果、预测 SQL、标准 SQL 以及对应评价指标，并分别统计 overall、two_table 和 three_table 三个层面的结果。

## 4.2 数据集

### 4.2.1 MMQA 数据集概述

本文实验基于 MMQA（Multi-Table Multi-Hop Question Answering）复杂多表多跳评测基准展开。该数据集围绕多表、多跳查询场景构建，问题往往需要跨越多张关系表完成实体定位、条件筛选、聚合计算或桥接表连接，因此相比单表问答或简单 Text-to-SQL 数据集更贴近真实数据库应用场景。

MMQA 的一个重要特点在于其问题不再局限于单张表内部的信息抽取，而是要求模型能够同时理解自然语言问题、多张表之间的结构关系以及主键、外键或桥接表在推理链中的作用。例如，一个问题表面上可能只提到“顾客”和“发票”，但如果要生成正确 SQL，往往还需要通过中间表才能建立完整连接。因此，该数据集非常适合用于评估多表检索与跨表 SQL 生成能力。

### 4.2.2 多表检索实验数据划分

在多表检索实验中，本文分别使用 MMQA 中构造好的二表和三表问题集，并配套使用相应的全局表池：

- 二表检索数据：`QA_SQL_two_table.json` 与 `global_table_pool_two.json`
- 三表检索数据：`QA_SQL_three_table.json` 与 `global_table_pool_three.json`

其中，二表问题集共包含 841 个测试问题，标准答案中每个问题对应 2 张关键表；三表问题集共包含 721 个测试问题，标准答案中每个问题对应 3 张关键表。实验中，系统需要从全局表池中为每个问题召回能够支撑后续多跳推理的关键表集合，再与标准表集合进行比对。

从任务难度上看，三表问题比二表问题更加复杂。一方面，三表问题通常涉及更多实体和更长的连接路径；另一方面，三表问题中桥接表和中间表出现得更频繁，模型不仅要识别与问题字面语义直接相关的表，还要发现语义不显著但结构上不可缺失的连接表。因此，三表任务更能体现结构传播策略的价值，也更容易暴露传播噪声控制不足的问题。

### 4.2.3 Text-to-SQL 实验数据划分

在 Text-to-SQL 实验中，本文使用预处理后的测试文件 `finetuning_test.jsonl`。该测试集共包含 332 条样本，其中：

- two_table 样本 255 条；
- three_table 样本 77 条。

每条样本均包含自然语言问题、对应的标准表头以及标准 SQL。与原始数据相比，本文在构建测试样本时删除了大量无关表内容，仅保留与 SQL 生成最直接相关的 Schema 信息。这样做的主要目的在于降低输入长度和噪声，使模型能够把更多注意力集中在表名、列名、连接关系和约束条件上。

此外，由于 Text-to-SQL 实验采用标准答案表头作为输入，因此该部分实验更适合反映模型在理想 Schema 条件下的 SQL 生成能力，而不受上游检索误召回或漏召回的影响。

## 4.3 评价指标

### 4.3.1 多表检索评价指标

对于多表检索实验，本文采用信息检索领域中的常用指标进行评估，包括 Recall、Precision、F1、MRR 和 MAP@K。

（1）Recall

Recall 用于衡量标准相关表中有多少被系统成功召回。在多表检索任务中，Recall 是最核心的指标之一，因为只要关键表漏召回，下游 SQL 生成通常就无法正确完成。若设标准相关表集合为 \(G\)，系统返回的 Top-K 表集合为 \(R\)，则 Recall 定义为：

\[
\mathrm{Recall} = \frac{|G \cap R|}{|G|}
\]

（2）Precision

Precision 用于衡量系统返回结果中有多少是真正相关的表，计算公式为：

\[
\mathrm{Precision} = \frac{|G \cap R|}{|R|}
\]

在本文的二表与三表实验中，由于最终返回的 Top-K 与标准答案表数一致，因此 Precision 与 Recall 在数值上保持一致，但 Precision 仍然可以反映系统是否在有限候选位中引入了无关表。

（3）F1

F1 是 Precision 与 Recall 的调和平均值，用于综合衡量检索结果的准确性与完整性，计算公式为：

\[
F1 = \frac{2 \times Precision \times Recall}{Precision + Recall}
\]

（4）MRR（Mean Reciprocal Rank）

MRR 用于衡量第一个相关表在排序结果中的位置。若第一个相关表出现在第 \(rank\) 位，则该问题的倒数排名为 \(1/rank\)，对所有问题求平均后得到 MRR。该指标能够反映系统是否能将关键表尽量排在前列。

（5）MAP@K（Mean Average Precision）

MAP@K 用于综合考察多个相关表在 Top-K 排名中的整体排序情况，比只关注首个命中位置的 MRR 更全面。在多表任务中，该指标能够反映系统是否同时兼顾了多个关键表的排序质量。

### 4.3.2 Text-to-SQL 评价指标

对于 Text-to-SQL 实验，本文采用原论文中较常见的文本相似性评价方式，而不执行 SQL 语义等价性验证或数据库执行验证。具体指标包括 JSON 格式正确率、ROUGE-1、ROUGE-L 和 BLEU。

（1）JSON 格式正确率

该指标衡量模型输出是否满足预设的 JSON 格式要求，即是否能够正确返回 `{"SQL": ...}` 形式的结果。由于本文的评测流程要求模型输出可自动解析的结构化结果，因此该指标可用于反映模型在指令遵循和格式控制方面的稳定性。

（2）ROUGE-1

ROUGE-1 主要衡量生成 SQL 与标准 SQL 在词级别上的重合程度，可以反映模型是否正确生成了较多关键列名、表名和条件关键词。

（3）ROUGE-L

ROUGE-L 基于最长公共子序列进行计算，能够在一定程度上反映生成 SQL 与标准 SQL 在整体结构上的相似性，对于多表连接、嵌套结构和条件排列更敏感。

（4）BLEU

BLEU 从 n-gram 匹配角度评价生成 SQL 与标准 SQL 的接近程度，对局部短语和结构片段的重合比较敏感。该指标可以与 ROUGE 形成互补，用于综合观察模型的文本生成效果。

需要说明的是，上述指标主要反映 SQL 文本与标准答案在表面形式上的接近程度，并不完全等价于 SQL 语义正确性。例如，不同写法的 SQL 可能语义等价，而文本相近的 SQL 也可能因连接条件错误而无法得到正确答案。因此，本文对 Text-to-SQL 的实验分析更侧重“生成能力比较”而非“执行结果正确率分析”。

## 4.4 实验结果

### 4.4.1 多表检索实验结果分析

#### （1）二表检索结果分析

表 4.1 给出了二表检索任务上的主要实验结果。

| 方法 | Recall | Precision | F1 | MRR | MAP@K |
| --- | ---: | ---: | ---: | ---: | ---: |
| E3\_PAPER | 0.2449 | 0.2449 | 0.2449 | 0.3811 | 0.2155 |
| E3 | 0.5178 | 0.5178 | 0.5178 | 0.7711 | 0.4896 |
| E4\_HYBRID | 0.5184 | 0.5184 | 0.5184 | 0.7854 | 0.4955 |
| E5\_HYBRID\_LOCAL | **0.5440** | **0.5440** | **0.5440** | **0.8068** | **0.5193** |

从表中可以看出，接近原始论文伪代码的 E3\_PAPER 表现最差，其 Recall 仅为 0.2449，MRR 为 0.3811。这说明在本文采用向量点积语义打分和当前表池表示方式的设定下，直接按照 paper-like 方式进行全量传播并不能取得稳定收益，反而容易引入较大传播噪声。

与 E3\_PAPER 相比，本文实现的完整 MTR 版本 E3 在二表任务上取得了显著提升，Recall 从 0.2449 提高到 0.5178，MRR 从 0.3811 提高到 0.7711，说明通过对子问题语义得分进行平均，并引入最大连通性截断与残差平滑后，传播过程的稳定性得到了明显改善。

在 E3 的基础上，E4\_HYBRID 进一步加入不确定性门控机制，其 Recall 达到 0.5184，MRR 达到 0.7854，相比 E3 有小幅提升。这表明并非所有问题都适合执行完整传播；在部分首轮语义排序已经较稳定的问题上，适当控制传播触发条件有助于减少额外噪声。

总体上表现最优的方法为 E5\_HYBRID\_LOCAL。该方法在 Recall、MRR 和 MAP@K 上均取得最佳结果，分别达到 0.5440、0.8068 和 0.5193。与 E3 相比，E5\_HYBRID\_LOCAL 的 Recall 提高了 0.0262，MRR 提高了 0.0357，说明将传播限制在局部候选池内，并在局部范围中进行结构扩展和重排，可以在保留桥接表发现能力的同时，有效抑制全局传播带来的噪声扩散。

进一步从逐题对比结果看，E3 相对 E3\_PAPER 在 841 个二表问题中共有 442 题得到改善，仅有 53 题退化，表明本文对 MTR 的改造相较于 paper-like 版本具有明显优势。相比之下，E4\_HYBRID 相对 E3 的改善题数为 31，退化题数为 30，说明门控传播虽然整体有益，但提升幅度相对有限；E5\_HYBRID\_LOCAL 相对 E3 则有 114 题改善、74 题退化，说明局部扩展与重排在更多样本上产生了稳定增益。

#### （2）三表检索结果分析

表 4.2 给出了三表检索任务上的主要实验结果。

| 方法 | Recall | Precision | F1 | MRR | MAP@K |
| --- | ---: | ---: | ---: | ---: | ---: |
| E3\_PAPER | 0.2742 | 0.2742 | 0.2742 | 0.4776 | 0.2294 |
| E3 | 0.4753 | 0.4753 | 0.4753 | 0.7025 | 0.4227 |
| E4\_HYBRID | 0.4938 | 0.4938 | 0.4938 | 0.7446 | 0.4429 |
| E5\_HYBRID\_LOCAL | **0.4961** | **0.4961** | **0.4961** | **0.7457** | **0.4458** |

与二表任务相似，E3\_PAPER 在三表场景下仍然表现最弱，其 Recall 仅为 0.2742。相比之下，E3 的 Recall 提高到 0.4753，MRR 提高到 0.7025，说明经过本文改造的完整 MTR 在三表复杂场景中同样明显优于 paper-like 版本。

进一步看，E4\_HYBRID 和 E5\_HYBRID\_LOCAL 在三表任务上都优于 E3，其中 E4\_HYBRID 的 Recall 为 0.4938，E5\_HYBRID\_LOCAL 的 Recall 为 0.4961；在 MRR 上，二者分别为 0.7446 和 0.7457。虽然 E4 与 E5 的差距在三表场景下不如二表明显，但 E5\_HYBRID\_LOCAL 仍然在主要指标上保持最优，说明局部扩展与重排策略在更复杂的多跳连接任务中依旧具备较好的稳定性。

从逐题对比结果看，E3 相对 E3\_PAPER 在 721 个三表问题中有 375 题改善，仅有 63 题退化，说明本文的完整 MTR 改进在三表场景中同样能够有效替代 paper-like 传播。E4\_HYBRID 相对 E3 有 59 题改善、30 题退化，显示出门控传播对复杂问题具有一定补偿作用；E5\_HYBRID\_LOCAL 相对 E3 有 152 题改善、107 题退化，虽然退化题数也有所增加，但其整体 Recall、MRR 和 MAP@K 依旧最高，说明该方法在更多样本上获得了更强的补表能力。

#### （3）多表检索结果讨论

综合二表和三表实验可以得到以下几点结论。

第一，paper-like 版本在本文当前实现设定下始终显著弱于其余方法，说明原论文中较为抽象的传播思路在缺少完整细节和原始打分模块时并不能直接迁移到本文的工程环境中。特别是在语义相似度从生成式打分改为向量点积之后，原始累加式传播更容易放大连通度高但语义不充分的表，从而引发误召回。

第二，本文实现的完整 MTR 版本 E3 对 E3\_PAPER 形成了稳定而显著的提升，说明问题分解、平均语义得分、最大连通性截断和残差平滑这几项改进共同提升了传播稳定性。

第三，在本文所有方法中，E5\_HYBRID\_LOCAL 在二表和三表任务上都取得了最优结果，说明“局部扩展 + 重排”比“全局无差别传播”更适合当前多表检索任务。其本质原因在于：桥接表的发现确实需要利用结构关系，但传播范围若覆盖整个表池，噪声会迅速累积；而局部候选池既保留了从种子表出发发现结构邻居的能力，又避免了大量无关表参与传播。

第四，E4\_HYBRID 虽然不如 E5\_HYBRID\_LOCAL 整体稳定，但相较于 E3 仍有一定提升，说明“是否传播”本身是值得建模的。并不是所有问题都需要结构传播，对简单问题或首轮语义排序已较清晰的问题，过度传播反而可能拉低排序质量。

在三表任务中，MiniMax-M2.5 的优势进一步扩大，ROUGE-1 达到 81.84，BLEU 达到 60.24，明显高于其余模型。deepseek-v4-flash 和 kimi-k2.6 也保持了较强表现，而 glm-5 与 qwen3.6-flash 则出现较明显下滑，说明不同模型在复杂跨表连接、约束组合和结构组织能力上存在明显差异。

#### （3）Text-to-SQL 结果讨论

综合 overall、two_table 和 three_table 的结果，可以得到以下结论。

第一，MiniMax-M2.5 是本文当前实验中整体表现最好的 API 模型。无论在总体、双表还是三表场景中，该模型都在主要文本相似性指标上保持领先，说明其在给定标准 Schema 条件下具备较强的 SQL 组织能力。

第二，deepseek-v4-flash 在格式稳定性方面表现最稳，其 JSON 格式正确率始终达到 100.00%，同时在文本相似性指标上也保持较高水平，说明该模型兼具较好的指令遵循能力和较强的生成能力。

第三，不同模型在三表场景中的表现差异大于双表场景。以 ROUGE-1 为例，MiniMax-M2.5 从双表的 73.17 提升到三表的 81.84，而 glm-5 则从双表的 73.14 降至三表的 69.21，qwen3.6-flash 也从 71.73 降至 70.71。这说明对于部分模型而言，三表样本并未简单带来更难的文本匹配问题，反而可能由于问题模式更规则、连接路径更明确，使强模型更容易发挥优势；但对另一些模型而言，表结构复杂度的提升会显著增加 SQL 组织难度。

第四，需要注意的是，本文的 Text-to-SQL 评价仍然基于文本相似性而非执行结果。也就是说，当前结果能够较好反映模型在 SQL 表达形式上的拟合能力，但尚不能完全等价于语义正确率。因此，这部分实验更适合作为不同模型生成能力的相对比较，而不是数据库可执行性层面的最终结论。

### 4.4.3 本章小结

本章从实验设置、数据集、评价指标和实验结果四个方面，对本文的多表多跳查询实验进行了系统分析。

在多表检索方面，实验表明：接近原始论文伪代码的 paper-like 传播方案在本文实现环境下效果较弱；本文改进后的完整 MTR 版本能够显著优于 paper-like 基线；进一步加入门控传播和局部扩展后，系统整体表现得到继续提升，其中 E5\_HYBRID\_LOCAL 在二表和三表任务上均取得最优结果。这说明在当前任务中，结构传播是有价值的，但其传播范围和触发条件必须受到控制，局部传播比全局传播更稳定。

在 Text-to-SQL 方面，实验表明：在给定正确 Schema 的前提下，不同原始大语言模型已经具备一定的跨表 SQL 生成能力，但模型之间差异依然显著。其中 MiniMax-M2.5 在文本相似性指标上整体最优，deepseek-v4-flash 在输出格式稳定性方面最强。该结果说明，当检索误差被屏蔽后，当前主流大语言模型已经能够在一定程度上完成复杂多表 SQL 生成，但在更高层次的语义正确性和执行正确性方面仍有进一步研究空间。

综上，本文的实验结果表明：分别从多表检索和 Text-to-SQL 两个方面进行分析，有助于更清晰地定位多表多跳查询任务中的性能瓶颈，也为后续系统优化和研究改进提供了明确方向。
