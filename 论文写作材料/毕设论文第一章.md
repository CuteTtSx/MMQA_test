# 第一章 绪论

## 1.1 课题背景

随着大语言模型（Large Language Models, LLMs）在自然语言理解、代码生成和复杂推理任务中的快速发展，利用自然语言直接访问结构化数据库逐渐成为数据库智能交互领域的重要研究方向。传统数据库查询通常要求用户掌握 SQL 等结构化查询语言，而在实际应用中，大量普通用户并不具备专业的数据库知识。因此，如何将用户以自然语言表达的信息需求自动转换为可执行的数据库查询，并进一步得到准确、可靠的查询答案，是自然语言处理与数据库技术交叉领域中的关键问题。

在单表或简单数据库场景中，已有的表格问答和 Text-to-SQL 方法能够取得较好的效果。然而，现实数据库往往由多张表组成，表与表之间通过主键、外键或中间桥接表形成复杂关联。当用户问题涉及多个实体、多个条件或多跳推理关系时，系统不仅需要理解自然语言问题本身，还需要判断哪些表共同构成回答该问题所需的证据链。例如，一个问题可能同时涉及学生、课程、注册记录和成绩等多张表，模型必须先找到相关表，再通过正确的连接关系生成查询逻辑。这类任务通常被称为多表多跳查询任务。

多表多跳查询相比普通单表问答具有更高难度，主要体现在以下几个方面。第一，大语言模型的上下文窗口和注意力分配能力有限。若将大量候选表及其表内容直接拼接到 Prompt 中，不仅会迅速增加输入长度，还可能使模型在冗余表结构和无关字段中分散注意力，从而降低 SQL 生成和最终答案推理的质量。因此，在复杂数据库场景中，通常需要先通过多表检索模块缩小候选表范围，再将更精确的表结构输入下游生成模块。第二，候选表空间更大。系统需要从全局表池中筛选出少量与问题相关的表，容易受到表名、列名相似但语义无关的干扰表影响。第三，问题语义更复杂。用户问题往往包含嵌套约束、比较、聚合、交集或多实体关联，直接使用原始问题进行检索容易出现语义漂移。第四，表间结构关系对结果影响显著。许多关键表本身与问题字面语义并不完全匹配，却承担连接其他表的桥接作用，若检索阶段漏召回这类表，下游 SQL 生成将难以正确完成。第五，端到端流水线容易产生级联误差。若先由检索模块召回候选表，再将候选表输入 SQL 生成模块，最终错误可能来自检索阶段，也可能来自 SQL 生成阶段，二者相互耦合后难以准确分析模型能力边界。

近年来，检索增强生成（Retrieval-Augmented Generation, RAG）框架被广泛用于开放域问答和知识密集型任务。该类方法通常先检索相关知识，再将检索结果输入大语言模型完成生成。在多表数据库问答任务中，这一思想同样具有必要性：多表检索的目标并不是“找表”本身，而是从大量候选表中筛选出能够支撑 SQL 生成和答案推理的关键表结构，避免将全部表格信息直接塞入大模型上下文窗口。然而，常规 RAG 式流水线并不能直接解决所有问题。一方面，表检索结果的质量会直接限制后续 SQL 生成和答案生成的上限；另一方面，大语言模型即便具备较强的代码生成能力，也可能因输入表结构不完整或包含过多无关表而生成错误 SQL。因此，仅从最终 SQL 执行结果或最终答案评价系统性能，难以判断错误究竟来自“相关表召回不足”还是“基于表结构生成 SQL 的能力不足”。

针对上述问题，Wu 等人在 ICLR 2025 提出了 MMQA（Multi-Table Multi-Hop Question Answering）复杂多表评测基准，用于评估大语言模型在多表、多跳场景下的理解、检索和推理能力。与 WikiTableQuestions、WikiSQL 等主要面向单表场景的数据集不同，MMQA 基准要求模型从多个相互关联的表格中抽取证据，识别主键和外键等结构关系，并通过多步推理回答复杂问题。该基准围绕四类任务构建了较完整的评估框架，包括多表检索、Text-to-SQL 生成、多表问答以及键选择任务，其中键选择又包含主键选择和外键选择两个子任务，更贴近现实数据库应用中跨表查询的复杂性。本文并未覆盖 MMQA 的全部评估任务，而是选择其中与系统链路最密切的多表检索和 Text-to-SQL 生成两个方面展开研究：前者负责从全局表池中筛选支持后续推理的关键表结构，后者负责在给定表结构的条件下生成可执行的 SQL 查询。

基于 MMQA 基准提出的问题设定，本文围绕多表多跳查询任务，设计并实现了一套解耦的评估与增强框架。该框架将任务拆分为两条相对独立的研究链路：一是多表检索链路，重点研究如何从全局表池中检索出支撑问题回答的关键表结构，以减少无关表对大模型上下文和注意力分配的干扰；二是 Text-to-SQL 生成链路，重点研究在已知标准表结构的前提下，大语言模型能否正确完成跨表 SQL 生成。通过这种解耦设计，本文希望更清晰地分析多表任务中的关键困难，并分别评估检索模块与 SQL 生成模块的能力。

在多表检索方面，本文参考 MMQA 论文中提出的 MTR（Multi-Table Retrieval）思想，关注问题分解、问题-表语义相似度计算以及表间结构传播机制。由于原始论文并未公开完整源码，且论文中对问题分解、表间相似度计算和传播细节的描述较为抽象，本文在复现实验过程中对算法进行了工程化改造：将原先基于生成式模型的问题-表相关性判断改为基于向量点积的语义相似度计算，并进一步设计了多种传播策略和消融实验，以分析不同检索机制在当前数据和实现条件下的有效性。在 Text-to-SQL 方面，本文采用标准表头（Oracle Schema）构造评估输入，降低检索噪声对 SQL 生成能力评估的干扰，并基于阿里百炼平台调用多种原始大语言模型 API，对其跨表 SQL 生成能力进行统一评测。

因此，本文课题具有一定的研究意义和工程价值。一方面，它基于最新提出的 MMQA 多表多跳评测基准，针对多表查询中的表检索与 SQL 生成两个关键环节进行解耦分析，有助于更准确地定位模型在复杂数据库任务中的能力短板；另一方面，本文实现了从数据预处理、表池构建、问题分解、多表检索到多模型 API 评估的完整流程，为后续多表问答系统研究提供了可复用的实验框架和阶段性实验参考。

需要说明的是，多表多跳问答目前仍缺少统一且成熟的解决方案，MMQA 原论文更多是提出评测基准并揭示现有大语言模型在复杂多表推理中的不足；本文同样并非声称完全解决该问题，而是在 MMQA 任务设定下对多表检索和 Text-to-SQL 两个关键环节进行复现、改进与实验分析。

## 1.2 本文主要工作

本文基于 ICLR 2025 提出的 MMQA（Multi-Table Multi-Hop Question Answering）复杂多表评测基准开展研究，重点探究复杂多表场景下的表检索方法、Text-to-SQL 生成方法以及二者的解耦式评估方式。本文主要工作如下：

（1）前期文献调研与任务分析。调研表格问答、Text-to-SQL、检索增强生成、多表检索以及 MMQA 多表多跳评测基准等相关研究资料，系统梳理传统表格问答方法、基于深度学习的语义解析方法以及基于大语言模型的数据库问答方法的发展脉络。在此基础上，重点分析 MMQA 任务相较于单表问答任务的难点，包括候选表空间较大、问题语义复杂、主外键关系识别困难、桥接表难以召回以及端到端流水线容易产生级联误差等问题。通过前期调研与任务分析，明确了以多表检索和 Text-to-SQL 生成为核心的研究思路，并确定了采用解耦式架构分别评估检索能力与生成能力的技术路线。

（2）多表多跳查询系统框架设计。本文围绕 MMQA 基准中的多表检索与 Text-to-SQL 任务，设计并实现了一套面向多表多跳查询任务的解耦式实验框架。该框架不直接采用“检索—生成”串联的端到端流水线，而是将系统划分为多表检索链路和 Text-to-SQL 生成链路。多表检索链路以全局表池和自然语言问题为输入，输出 Top-K 候选表，并通过 Recall、Precision、F1、MRR、MAP 等指标独立评价检索效果；Text-to-SQL 链路则采用标准答案表头作为输入，重点考察大语言模型在已知正确 Schema 条件下生成跨表 SQL 的能力。通过这种模块化设计，本文能够更准确地区分检索阶段错误和 SQL 生成阶段错误，为后续实验分析提供清晰依据。

（3）多表检索算法设计与工程实现。针对 MMQA 中复杂问题直接检索容易发生语义漂移的问题，本文引入问题分解模块，利用大语言模型将原始多跳问题拆解为若干有序子问题，为表检索过程提供更细粒度的语义信息。在问题-表语义相似度计算方面，本文将候选表的表名和列名组织为结构化 Schema 文本，并利用密集向量模型将问题和表结构映射到同一向量空间，通过向量点积计算二者的语义相关性。考虑到多表查询中部分桥接表与问题字面语义关联较弱，本文进一步引入表间结构关系传播机制，通过主外键关系或表结构相似性刻画表与表之间的联系，从而提高对关键关联表的召回能力。

（4）多表检索消融实验与改进策略设计。由于 MMQA 论文未公开完整源码，且论文中对问题分解、表间相似度计算和传播细节的描述不够精确，本文首先实现了接近论文伪代码的 paper-like 版本作为对照。实验过程中发现，在本文将语义相似度计算由生成式模型改为向量点积后，完全照搬原始传播流程容易产生传播噪声累积和高连通表分数放大等问题。基于这一现象，本文提出了改进版完整 MTR 方法 E1，在子问题平均语义得分的基础上引入最大连通性截断和残差平滑机制，以提高传播稳定性。进一步地，本文在 E1 基础上设计了 E2_HYBRID 和 E2_HYBRID_LOCAL 两种策略，分别从传播触发条件和传播候选范围两个角度减少全局传播带来的噪声和计算成本。通过这些消融实验，本文分析了不同传播机制在多表检索任务中的作用和局限。

（5）Text-to-SQL 评估流程设计。为避免检索错误影响 SQL 生成能力评估，本文在 Text-to-SQL 链路中采用标准表头作为输入，直接使用 MMQA 样本对应的真实表结构构造测试样本。在数据构建过程中，本文去除原始数据中庞大的表内容字段，仅保留与 SQL 生成密切相关的表名、列名和问题信息，以降低输入长度和噪声干扰。在模型评估方面，本文不再对模型进行额外微调，而是基于阿里百炼平台统一调用多种原始大语言模型 API，在相同输入格式和输出要求下比较其跨表 SQL 生成能力。该部分实验用于评估不同大语言模型在给定正确表结构时的跨表连接、条件筛选和 SQL 代码生成能力。

（6）系统实验评估与结果分析。本文实现了完整的实验运行和评估工具，支持 MMQA 二表和三表多表检索任务的批量评估，并能够输出不同 Top-K 设置下的多项检索指标。通过对纯语义检索、问题分解、paper-like 传播、改进版 E1、E2_HYBRID 以及 E2_HYBRID_LOCAL 等方法进行对比，本文分析了语义检索、问题分解和结构传播在多表检索任务中的实际效果。同时，本文对基于阿里百炼平台的多模型 Text-to-SQL 生成结果进行整理与分析，总结当前系统在多表多跳查询任务中的优势、不足以及后续改进方向。

## 1.3 章节安排

本文主要包含以下几个部分的内容：

第一章绪论，主要介绍课题研究背景与意义，说明 MMQA 多表多跳查询任务的研究难点，概述本文主要工作和论文的组织结构。

第二章相关工作与理论基础，主要介绍本文涉及的相关技术和研究背景，包括单表问答、Text-to-SQL、面向表格推理的大语言模型、多表任务、MMQA 评测基准、密集向量检索、问题分解方法以及常用检索与文本相似性评价指标等，为后续章节的系统设计与实验分析提供基础。

第三章基于大语言模型的多表多跳查询系统设计与实现，主要介绍本文提出的解耦式系统架构，详细阐述多表检索模块、问题分解模块、表间结构传播机制、检索消融实验变体以及基于标准表头的 Text-to-SQL 评估流程。

第四章实验结果与分析，主要介绍实验数据、实验设置和评价指标，并在 MMQA 多表检索任务上对不同算法变体进行定量对比和消融分析；同时对 Text-to-SQL 生成结果进行分析，总结系统在复杂多表查询场景下的表现。

第五章总结与展望，主要总结本文的研究内容和实验结论，分析当前方法在问题分解稳定性、表间关系建模、全局传播噪声控制以及 SQL 生成准确性等方面存在的不足，并提出未来可能的改进方向。
