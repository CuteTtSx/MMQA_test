# 第三章 基于大模型的多表多跳查询系统设计与实现

传统的“检索-增强生成（RAG）”架构通常将检索与生成模块串联，但在处理复杂多表多跳任务时，这种强耦合的端到端设计会引发级联误差，掩盖大语言模型（LLMs）在单一维度的真实缺陷。为了精准探测与提升 LLMs 在多表环境下的能力边界，本文摒弃了常规的流水线系统，设计并实现了一套解耦的评估与增强框架。本章将详细阐述该解耦架构的设计理念，并深入解析多表检索（MTR）以及 Text-to-SQL 两大核心模块的具体工程实现细节。

## 3.1 系统总体架构

传统的表格问答系统多采用端到端（End-to-End）的流水线架构，即先由检索模块寻找相关表，再将检索结果（表）直接输入至 SQL 生成模块。然而，在复杂的多表多跳场景中，检索阶段引入的微小误差（如漏召回关键桥接表、误召回强干扰表）会不可逆地传递给下游的生成模块（级联误差），导致研究者无法准确判断最终的失败是源于“检索能力不足”还是“代码生成能力不足”。

为了精准定标大语言模型在各项核心任务上的能力边界，本文摒弃了容易掩盖问题的流水线设计，转而采用一种严格解耦的模块化架构（Decoupled Modular Architecture）。系统总体架构分为两条在评估阶段互相独立的链路：表检索链路与 SQL 生成链路。

**图 3.1 解耦的模块化系统架构图**

> - 左边框：多表检索模块（MTR）  
>   输入：全量数据库表池 + 复杂问题  
>   输出：Top-K 候选表 + 检索指标评估
> - 右边框：Text-to-SQL 生成模块  
>   输入：标准答案表头（Oracle Schema） + 复杂问题  
>   输出：生成 SQL + 语法和语义评估

具体工作模式如下：

多表检索链路 (MTR)：负责在庞大的全量全局表池（Global Table Pool）中，寻找解决复杂问题所需的表格子集。该模块包含问题分解器与迭代检索打分器，最终输出 Top-K 的表结构集合并进行 Precision、Recall 等检索指标的独立测算。 

Text-to-SQL 生成链路：为了屏蔽检索噪声，此链路的数据预处理阶段直接提取了包含绝对正确表结构的“标准表头（Ground Truth Schema）”。该标准 Schema 与原问题被组装为提示词输入大语言模型，重点考察模型在已知正确表结构的前提下，正确映射列名并编写复杂连表 SQL 语法的核心推理能力。

## 3.2 问题分解模块

在现实场景的复杂多跳查询中，用户的问题往往包含深层的逻辑嵌套（如交集、聚合计算等）。直接将此类长难句输入传统检索模型（如 BM25 或单表密集检索模型）容易导致“语义漂移”（Semantic Drift），使得检索系统抓取到错误的相关表。为此，本文引入了问题分解机制，**旨在将复杂的推理黑盒转化为可观测的离散步骤，从而为多表检索（MTR）模块的独立评估提供细粒度的语义锚点。**

### 3.2.1 基于少样本学习的分解器构建

本文利用大语言模型强大的上下文学习与指令遵循能力构建了问题分解器。为了确保分解过程符合关系型数据库的查询逻辑，并在工程实现上保持输出格式的稳定性，本文采用了少样本提示（Few-shot Prompting）策略。

系统提示词明确要求模型将复杂问题拆解为 2 至 5 个可独立回答的子问题，且子问题的顺序必须符合原始问题的内在逻辑。

#### 表 3.1 问题分解模块的核心提示词与示例

| **模块**              | **提示词与输入输出内容**                                     |
| --------------------- | ------------------------------------------------------------ |
| **System Prompt**    | You are an expert at multi-hop question decomposition. Your task is to decompose complex multi-hop questions into simpler sub-questions that can be answered sequentially... Output ONLY valid JSON in the format: {"sub_questions": [...]} |
| **Few-shot Example** | **Question:** What are the names of heads serving as temporary acting heads in departments with rankings better than 5? **Sub-questions:** 1. Which departments have rankings better than 5? 2. Who are the temporary acting heads in these departments? 3. What are the names of these heads? |
| **User Input**       | [Question] {原始多跳问题}                                   |

### 3.2.2 鲁棒性控制与异常处理

在实际运行中，大模型的输出具有一定的随机性。为了保障**检索模块在批量自动化评估时的连续性与可靠性**，本模块在工程实现上引入了如下鲁棒性控制机制：

1. **长度截断与清洗**：解析大模型返回的 JSON 对象后，若生成的子问题链过长（超过5个），系统会执行强制截断，以防止过度发散引入检索噪声。
2. **退回机制与异常重试**：当大模型因网络波动或遇到极端复杂问题导致 JSON 解析失败时，系统设计了指数退避的重试机制。若达到最大重试次数依然失败，系统不会中断测试程序，而是触发“安全回退（Fallback）”，直接返回原始问题作为下一步的检索输入，从而保障批量评估程序的容错率。
3. **哈希缓存加速**：通过对原始问题计算 MD5 哈希值，系统实现了本地缓存机制，降低了重复实验过程中的 API 调用开销与延迟。

## 3.3 多表迭代检索 (MTR) 算法设计

在将原始长难句拆解为子问题序列后，系统进入核心的多表迭代检索阶段。与传统单表检索仅依赖语义匹配不同，多表检索任务（MTR）面临着“语义漂移”与“孤岛表格”两大挑战。为此，本文以融合“语义相似度”与“表间结构关系”的双流打分思想为基础，并在工程实现上对问题-表打分、表间关系传播以及候选表更新策略进行了改造，引入最大连通性截断与残差平滑策略以优化迭代传播过程。

### 3.3.1 双流打分机制

本模块将数据库视为一个由表节点（Tables）和主外键边（Foreign Keys）构成的关系图。对于任意给定的子问题 $q_i$ 与候选表 $T_j$，检索器同时考虑问题与表之间的语义匹配程度，以及候选表与已检索表之间的结构关联程度。二者分别记为语义相似度 $\alpha$ 和拓扑连通度 $\beta$。

**1. 语义相似度计算 ($\alpha$)**

语义得分主要衡量自然语言问题与表格模式（Schema）的字面及深层语义匹配度。原有的 MTR 算法采用基于大语言模型（如 TableLlama-7B）的生成式打分方法，该方法虽具备较强的理解能力，但在大规模表池中存在算力消耗大、推理延迟高的性能瓶颈。

为了兼顾检索精度与运行效率，本文对语义打分模块进行了向量化（Vectorization）改造。在具体实现中，本文首先将候选表 $T_j$ 的表头元信息（包含表名及所有列名）格式化为结构化文本。随后，利用基于 Transformer 架构的密集嵌入模型（Dense Embedding Model），将分离的子问题文本 $q_i$ 与表文本分别映射至统一的高维稠密向量空间。语义相似度 $\alpha(q_i, T_j)$ 最终通过计算二者的高维特征向量内积（Dot Product）得出：

$$\alpha(q_i, T_j) = \text{Embedding}(q_i) \cdot \text{Embedding}(T_j)$$

该方法将问题-表匹配过程由自回归生成转化为向量相似度计算，使系统能够更高效地完成全局表池扫描。

**2. 拓扑连通度计算 ($\beta$)**

大语言模型或向量模型在处理形如“ID”、“Name”等通用列名时容易赋予无关表格较高的语义得分。为此，本文引入基于底层数据库物理结构的拓扑连通度 $\beta$。设上一轮检索保留的锚点表集合为 $C_{t-1}$，对于当前评估的候选表 $T_j$，系统校验其与锚点表 $T_k \in C_{t-1}$ 之间的主外键（PK-FK）依赖关系。

若 $T_k$ 与 $T_j$ 存在明确的主外键映射或共享外键（如桥接表关系），则判定为强连通，赋值得分 $\beta(T_k, T_j) = 1.0$；若两者在物理层面上相互独立（即“孤岛表”），则仅保留基础底分 $\beta(T_k, T_j) = 0.1$。该机制通过结构逻辑约束过滤高语义但结构无关的干扰表。

### 3.3.2 迭代传播与残差平滑策略

原有的图注意力传播算法在多轮迭代中可能因过度累加导致中心表（连通边较多的基础表）分数异常膨胀，产生“雪球效应”。为解决此问题，本文在 MTR 迭代流水线中进行了两项关键的算法改良。

**1. 最大连通性截断 (Max-Connectivity)**

在第 $t$ 轮迭代中，对于候选表 $T_j$，算法不再累加其与所有锚点表的连通得分，而是仅取最强的一条连接路径。结合子问题集 $Q$，候选表的传播得分 $S_{prop}$ 计算如下：

$$S_{prop}(T_j)=\frac{1}{|Q|}\sum_{q_i \in Q}\left(\alpha(q_i, T_j)\times\max_{T_k \in C_{t-1}}\beta(T_k, T_j)\right)$$

该策略避免多个弱连接关系的简单累加对候选表排名造成过度放大，使算法更关注最可靠的结构连接路径。

**2. 动量残差保留 (Momentum Smoothing)**

在多轮网络传播中，初始轮次捕获的高纯度语义信息可能被后续复杂的图拓扑特征稀释。为此，本文在每轮分数更新时引入残差连接思想。最终得分 $S_{new}$ 由当前轮的传播得分 $S_{prop}$ 与上一轮的历史得分 $S_{old}$ 加权融合而成：

$$S_{new}(T_j)=\lambda\cdot S_{prop}(T_j)+(1-\lambda)\cdot S_{old}(T_j)$$

在本文实验中，设 $\lambda = 0.8$。该平滑因子使算法在向外探索新表的同时，保留初始语义排序中的有效信息，从而提升检索排名的稳定性。

### 3.3.3 多表检索算法变体设计

由于原始 MTR 论文并未公开完整源码，且论文正文对问题分解策略、表间相似度计算以及多轮传播中的候选表更新细节描述较为抽象，直接进行一比一复现存在一定困难。与此同时，本文在工程实现中对原文的语义相似度计算方式进行了调整：原方法倾向于使用类似 TableLlama 的生成式模型对问题-表相关性进行判断，而本文为了降低全局表池扫描的计算成本，将问题-表语义相似度改造为向量点积形式。因此，本文最初实现的语义相似度模块与表间相似度模块不可避免地与原文设定存在差异。实验过程中发现，完全按照论文伪代码思路构建的 paper-like 版本在当前向量化语义打分与本地表池表示下效果并不理想，容易出现传播噪声累积和高连通表得分放大的问题。基于这一观察，本文进一步提出了改进后的 E1 方法，并在 E1 的基础上继续设计了两种 E2 级别的混合改进策略。

为便于形式化描述，设全局表池为 $\mathcal{T}=\{T_1,T_2,\ldots,T_n\}$，问题分解后得到的子问题集合为 $Q=\{q_1,q_2,\ldots,q_m\}$，问题-表语义相似度为 $\alpha(q_i,T_j)$，表间结构连通度为 $\beta(T_k,T_j)$，第 $t$ 轮保留的候选表集合为 $C_t$。本文重点比较如下四类检索策略：首先以 E1\_PAPER 作为接近原始论文伪代码的对照版本，然后以 E1 作为本文主改进版本，最后在 E1 基础上构造 E2\_HYBRID 与 E2\_HYBRID\_LOCAL 两个进一步优化版本。

**1. E1：基于 paper-like 复现问题的改进版完整 MTR**

E1 是本文在 E1\_PAPER 复现效果不理想的基础上提出的主检索算法。由于本文将原文中的生成式问题-表打分替换为向量点积，首轮语义分数的分布特征与原文并不完全一致；同时，原文对表间相似度和传播细节描述不够精确，直接累加传播容易使部分高连通表获得过高分数。为适配本文的向量化语义打分方式，E1 对传播流程进行了两点改进：一是对子问题语义得分进行平均，以减轻单个子问题误差；二是在传播时采用最大连通性截断与残差平滑，以抑制传播噪声。

该策略首先利用问题分解模块将原始复杂问题 $q$ 拆解为子问题集合 $Q$，随后计算每张候选表在所有子问题上的平均语义得分，并选取首轮 Top-K 候选表作为传播锚点集合。首轮语义得分定义为：

$$S_0(T_j)=\frac{1}{|Q|}\sum_{q_i\in Q}\alpha(q_i,T_j)$$

首轮候选表集合为：

$$C_0=\operatorname{TopK}_{T_j\in\mathcal{T}}S_0(T_j)$$

在后续传播阶段，算法以 $C_{t-1}$ 作为上一轮锚点集合，对全局表池中的候选表重新打分。为了避免多个弱连接关系累加导致中心表分数异常放大，E1 采用最大连通性截断策略，仅保留候选表 $T_j$ 与上一轮候选集合 $C_{t-1}$ 之间的最强结构连接：

$$S_{prop}^{(t)}(T_j)=\frac{1}{|Q|}\sum_{q_i\in Q}\left(\alpha(q_i,T_j)\cdot \max_{T_k\in C_{t-1}}\beta(T_k,T_j)\right)$$

随后引入残差平滑，将当前轮传播得分与上一轮历史得分融合：

$$S_t(T_j)=\lambda S_{prop}^{(t)}(T_j)+(1-\lambda)S_{t-1}(T_j)$$

其中 $\lambda$ 为传播得分权重。最终第 $t$ 轮候选表集合更新为：

$$C_t=\operatorname{TopK}_{T_j\in\mathcal{T}}S_t(T_j)$$

E1 的功能是评估在 paper-like 复现不稳定的情况下，本文针对向量化语义打分和局部表结构表示所做的传播改进是否有效。它既利用子问题降低复杂问题的语义漂移，又利用表间结构关系补充语义检索难以发现的桥接表，并通过最大连通性截断与残差平滑控制传播噪声，因此是本文后续 E2 系列混合策略的基础方法。

**2. E1\_PAPER：接近原始伪代码的 MTR 传播策略**

E1\_PAPER 用于对照本文改进版传播策略与原始 MTR 思想之间的差异。由于原文源码并未公开，本文依据论文中的伪代码和文字描述实现了一个尽量贴近原始流程的 paper-like 版本。该策略首先使用原始问题 $q$ 而非子问题均值完成首轮语义检索，其初始得分为：

$$\Gamma_0(T_j)=\alpha(q,T_j)$$

对应的首轮候选集合为：

$$C_0=\operatorname{TopK}_{T_j\in\mathcal{T}}\Gamma_0(T_j)$$

随后算法按照子问题序列逐轮执行传播。对于第 $i$ 个子问题 $q_i$，候选表 $T_j$ 的传播贡献由其与当前子问题的语义相似度以及其与上一轮锚点表之间的结构关系共同决定。与 E1 的最大连通性截断不同，E1\_PAPER 更接近累加式传播流程，其更新方式可表示为：

$$\Gamma_i(T_j)=\Gamma_{i-1}(T_j)+\sum_{T_k\in C_{i-1}}\alpha(q_i,T_j)\cdot\beta(T_k,T_j)$$

每轮传播后重新选择 Top-K 候选表：

$$C_i=\operatorname{TopK}_{T_j\in\mathcal{T}}\Gamma_i(T_j)$$

E1\_PAPER 的功能是作为 paper-like 对照组，观察原始累加式传播在当前任务和本文工程设定下的表现。该方法能够检验在语义相似度已由生成式模型改为向量点积、表间关系细节需要自行实现的情况下，直接照搬论文传播框架是否会产生中心表放大、传播噪声累积等问题。该对照结果也是本文提出 E1 改进策略的重要依据。

**3. E2\_HYBRID：不确定性门控传播策略**

E2\_HYBRID 是在 E1 基础上的进一步改进，其设计动机是避免对所有问题无差别启用结构传播。E1 虽然通过最大连通性截断和残差平滑缓解了 paper-like 版本中的噪声累积问题，但对于部分简单问题而言，首轮语义检索已经能够形成较稳定的候选排序，此时继续执行完整传播仍可能引入额外结构噪声；而对于候选表得分接近的问题，语义检索存在不确定性，此时 E1 的结构传播可能带来补充收益。

该策略首先使用原始问题执行一次语义检索，得到基线语义得分：

$$S_{base}(T_j)=\alpha(q,T_j)$$

将所有候选表按照 $S_{base}$ 降序排列，设前三名得分分别为 $s_1$、$s_2$ 和 $s_3$，定义排序间隔：

$$\Delta_{12}=s_1-s_2$$

$$\Delta_{13}=s_1-s_3$$

若排序间隔较小，说明首轮语义排序置信度不足，系统启用完整 MTR 传播；否则直接采用基线语义检索结果。其门控函数可表示为：

$$g(q)=\begin{cases}
1, & \Delta_{12}\le \tau_{12}\ \text{or}\ \Delta_{13}\le \tau_{13} \\
0, & \text{otherwise}
\end{cases}$$

最终检索得分为：

$$S_{E2}(T_j)=\begin{cases}
S_{E1}(T_j), & g(q)=1 \\
S_{base}(T_j), & g(q)=0
\end{cases}$$

其中 $S_{E1}(T_j)$ 表示完整 MTR 传播后的得分。E2\_HYBRID 的功能是在 E1 的基础上引入传播触发条件，根据首轮语义排序的不确定性选择是否启用传播机制，从而在复杂问题上保留 E1 的结构补充能力，在简单问题上避免不必要的传播噪声和计算开销。

**4. E2\_HYBRID\_LOCAL：局部扩展与候选池内重排策略**

E2\_HYBRID\_LOCAL 同样是在 E1 基础上的进一步改进，其设计目标是降低全局传播带来的计算开销和噪声扩散。E1 在每轮传播时仍需要面向全局表池更新候选表得分，虽然这种方式保留了较强的全局探索能力，但也可能使大量无关表参与传播。为此，E2\_HYBRID\_LOCAL 将 E1 的传播范围从全局表池压缩到由语义种子表及其结构邻居构成的局部候选池中。该策略首先使用原始问题进行语义检索，得到种子表集合：

$$S_{base}(T_j)=\alpha(q,T_j)$$

$$C_{seed}=\operatorname{TopK}_{T_j\in\mathcal{T}}S_{base}(T_j)$$

随后以种子表为中心，根据表间结构关系从全局表池中扩展少量邻居表。对于某个种子表 $T_s\in C_{seed}$，候选邻居表 $T_j$ 的局部扩展得分可表示为：

$$S_{expand}(T_j\mid T_s)=\mu S_{base}(T_j)+(1-\mu)\beta(T_s,T_j)$$

其中 $\mu$ 用于平衡语义相关性与结构连通性。局部候选池由种子表及其高分邻居表共同构成：

$$C_{local}=C_{seed}\cup \operatorname{TopL}_{T_j\in\mathcal{T}\setminus C_{seed}}S_{expand}(T_j\mid T_s)$$

与 E1 在传播阶段仍面向全局表池不同，E2\_HYBRID\_LOCAL 只在局部候选池 $C_{local}$ 内进行传播与重排。对于 $T_j\in C_{local}$，其局部传播得分为：

$$S_{local\_prop}(T_j)=\frac{1}{|Q|}\sum_{q_i\in Q}\left(\alpha(q_i,T_j)\cdot\max_{T_k\in C_{local}}\beta(T_k,T_j)\right)$$

最终重排得分将候选表的原始语义得分与局部传播增益加权融合：

$$S_{local}(T_j)=\rho S_{base}(T_j)+(1-\rho)S_{local\_prop}(T_j)$$

其中 $\rho$ 为语义保留权重。E2\_HYBRID\_LOCAL 的功能是在 E1 的基础上约束传播空间，将传播范围从全局表池压缩到局部候选池，减少无关表参与传播造成的噪声，同时保留从种子表出发发现桥接表和结构邻居表的能力。该策略适用于检索空间较大、全局传播成本较高或干扰表较多的场景。

通过上述四类策略的对比，本文形成了一条由复现到改进、再到局部优化的实验故事线：E1\_PAPER 用于刻画在缺少原始源码且细节描述不充分时，直接依据论文伪代码复现 MTR 的效果；E1 针对 paper-like 版本在向量化语义打分条件下暴露出的传播噪声问题，引入平均子问题语义得分、最大连通性截断和残差平滑；E2\_HYBRID 与 E2\_HYBRID\_LOCAL 则进一步在 E1 基础上分别从传播触发条件和传播候选范围两个角度进行优化。该设计为后续实验章节中的消融分析提供了清晰的方法演进依据。

## 3.4 Text-to-SQL 评估模块

在多表多跳查询系统中，Text-to-SQL 模块的核心任务是将用户的自然语言问题转换为结构化 SQL 查询。为了严格剥离检索阶段可能带来的级联误差，精准评估大语言模型在跨表连接、条件筛选和查询结构组织方面的原始能力，本文在 Text-to-SQL 环节采用了“标准视角（Oracle）”的解耦设计，即不将检索结果直接送入下游模型，而是直接向模型提供与样本对应的正确表结构。

与早期方案中可能采用的本地微调路线不同，本文当前的 Text-to-SQL 模块不再以训练专门模型为目标，而是基于阿里百炼平台统一调用多个原始大语言模型 API，在相同输入格式和输出约束下，对其 SQL 生成能力进行横向评测。通过这一设计，系统能够更清晰地回答一个关键问题：在已知正确 Schema 的前提下，不同大语言模型本身是否具备完成复杂跨表 SQL 生成的能力。

### 3.4.1 基于标准表头的评测数据构建

大语言模型处理长上下文时容易出现注意力分散和关键信息覆盖不足的问题，而 MMQA 原始样本中包含大量表内容信息，若直接输入，不仅会显著增加提示词长度，还可能干扰模型对关键列名、表间关系和问题约束的识别。因此，本文在构建 Text-to-SQL 评测样本时采用了严格的数据降噪策略。

具体而言，系统在预处理阶段保留与 SQL 生成直接相关的结构化 Schema 信息，即表名与列名集合，并移除庞大的表内容字段。最终，输入给大语言模型的内容主要由三部分组成：系统提示词、自然语言问题以及对应的标准表头（Oracle Schema）。这种构造方式具有两方面优势：其一，可以有效压缩输入长度，降低无关表内容对模型注意力的干扰；其二，可以保证不同模型面对完全一致的 Schema 条件，从而使实验结果更具有可比性。

表 3.2 Text-to-SQL API 评测阶段的输入输出格式

**示例**：

| **角色 (Role)** | **内容示例 (Content)** |
| --------------- | ------------------------------------------------------------ |
| **System** | You are an expert at text-to-SQL. Generate a SQL query based on the given multi-hop question and the provided table schemas... |
| **User** | [Question] Which employee has certificates for aircrafts... [Tables] Table 1: employee Columns: Employee_ID, Name, Salary... |
| **Assistant** | {"SQL": "SELECT employee.Name FROM employee INNER JOIN ..."} |

在实际构造过程中，本文仍然采用与前文一致的 ChatML 风格消息格式，将问题和标准表头组织为模型可直接消费的对话输入，并要求模型输出仅包含 SQL 字段的 JSON 结果。这样既便于后续统一解析，也便于使用相同的评估脚本对不同模型进行自动化批量测试。

### 3.4.2 基于阿里百炼平台的多模型 API 评测实现

在模型执行层面，本文使用阿里百炼平台提供的 OpenAI 兼容接口，对多个原始大语言模型进行统一调用。系统通过配置固定的请求格式、温度参数和输出约束，将同一批测试样本分别发送给不同模型，并收集其返回结果。当前纳入评测的模型包括 Qwen3.6-flash、DeepSeek-V4-Flash、Kimi-K2.6、MiniMax-M2.5 和 GLM-5.1 五种代表性模型。

在工程实现上，评测脚本首先读取测试集样本，对每条样本提取问题与标准表头，并组装为 API 所需的 messages 结构。随后系统通过阿里百炼兼容接口向目标模型发起请求，获取生成结果后，自动执行 JSON 解析、SQL 字段提取、异常重试以及结果落盘。为了保证批量评测的稳定性，脚本中还设计了请求超时控制、失败重试和结果分模型存储等机制，从而提升大规模实验过程中的容错性与可复现性。

对于模型返回内容，系统优先检查输出是否满足预设 JSON 格式；若返回文本中包含可解析的 JSON 片段，则进一步抽取其中的 SQL 字段。最终，所有样本的原始输出、解析结果、标准 SQL 和评价指标都会被统一保存，形成可用于后续实验统计和对比分析的结构化结果文件。

### 3.4.3 评测输出与指标对接机制

为了保持 Text-to-SQL 评测流程与第四章实验分析的一致性，本文在系统实现中对每个模型分别输出两类结果文件：一类是逐样本预测明细文件，记录模型原始输出、解析后的 SQL、标准 SQL 以及单样本级别的相似性得分；另一类是汇总指标文件，记录 overall、two_table 和 three_table 三个层面的整体结果。

在指标计算方面，系统沿用 MMQA 原论文中对 Text-to-SQL 的基本评估思路，重点从输出格式约束与文本相似性两个角度分析模型表现。具体包括：JSON 格式正确率，用于衡量模型是否遵循预设结构化输出要求；ROUGE-1 和 ROUGE-L，用于比较生成 SQL 与标准 SQL 在词级和整体结构层面的相似程度；BLEU，用于从 n-gram 匹配角度衡量二者的文本接近程度。通过这种统一的评测与落盘机制，本文能够对多个 API 模型的 SQL 生成能力进行横向对比，并为后续结果分析与图表绘制提供标准化数据支撑。
